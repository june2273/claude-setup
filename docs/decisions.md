# 설계 결정 기록

각 항목은 **문제 → 선택 → 버린 대안 → 트레이드오프** 순서로 적는다.

판단 기준은 두 가지다.
- **언제 컨텍스트에 들어오는가.** 항상 로드되는가, 필요할 때만 로드되는가.
- **제안인가 보장인가.** CLAUDE.md와 스킬은 모델이 따르기를 기대하는 제안이고, hook은 실행되는 보장이다.

---

## D1. caveman은 기본 off

- **문제:** oh-my-fable은 "진행 보고와 마무리 요약"을, caveman은 "군더더기 제거"를 요구한다. 둘 다 상시로 켜면 출력 규칙이 충돌한다.
- **선택:** `config/caveman.json`에서 `defaultMode: "off"`로 둔다. 긴 구현 세션에서만 `/caveman`으로 켠다.
- **버린 대안:** 항상 켜기, 또는 플러그인 제거.
- **트레이드오프:** 출력 압축을 상시로 얻지 못한다. 대신 설명 품질과 규칙의 일관성을 지킨다.

## D2. Karpathy Skills와 Ponytail을 둘 다 유지

- **문제:** "단순하게"라는 원칙이 겹친다.
- **판단:** 방향이 같아서 충돌이 아니라 중복이다. Karpathy Skills는 스킬 방식이라 평소에는 설명 한 줄만 로드된다.
- **결과:** 상시로 강제하는 규칙은 Ponytail 하나로 두고, Karpathy Skills는 리뷰나 리팩터링 때 불러 쓴다.

## D3. Superpowers는 전역으로 도입하지 않음

- **문제:** Superpowers는 질문 → 설계 → 워크트리 → TDD → 리뷰 절차를 강제한다. 주 작업이 오디오/ML 연구 코드라, 이 절차가 실험 속도를 떨어뜨린다.
- **충돌:** oh-my-fable과 지시가 반대된다. 시작할 때 "바로 실행"과 "먼저 질문", 테스트에서 "요청 시에만"과 "TDD 필수"가 부딪힌다.
- **선택:** 전역으로는 oh-my-fable을 쓴다. 제품형 저장소에서만 프로젝트 `settings.json`의 `enabledPlugins`로 Superpowers를 켠다.
- **트레이드오프:** 커뮤니티 검증은 Superpowers 쪽이 훨씬 크다. 그래도 작업 성격에 맞는 쪽을 골랐다.

## D4. Serena 대신 LSP 플러그인 (검토 단계, 미설치)

- **판단:** graphify로 본 주 저장소는 하위 프로젝트 여러 개가 모인 중간 규모 연구 모노레포였다. Serena는 graphify(구조 파악)와도, LSP(심볼 탐색)와도 겹치고, MCP 도구가 추가되는 만큼 컨텍스트도 늘어난다.
- **재검토 조건:** 저장소가 커져 여러 파일에 걸친 리팩터링이 잦아질 때.

## D5. 모든 도구를 user scope로 설치

- **이유:** 이미 있던 프로젝트를 포함해 모든 프로젝트에 자동으로 적용된다.
- **예외 처리:** 프로젝트마다 다르게 하고 싶으면 `.caveman.json`이나 프로젝트 `settings.json`으로 덮어쓴다.

## D6. 산출물 저장 규칙을 CLAUDE.md로 고정

- **문제:** 세션마다 결과물이 임시 폴더에 흩어지고, 세션을 지우면 함께 사라진다.
- **선택:** `~/Downloads/claude/<YYMMDD>_<주제>/`에 `주제_파일명` 형식으로 저장하도록 전역 규칙에 넣었다.

## D7. 실제 키 노출 사고 → 규칙과 훅을 짝지음

- **사고:** 작업 중 두 가지가 커밋 대상에 섞였다. 배포된 클라우드 주소, 그리고 Notion 토큰이다.
- **원인:** "비밀값은 코드에 쓰지 말라"는 규칙이 없었다. 규칙이 있었더라도 모델은 지킬 수도 있고 안 지킬 수도 있다.
- **선택 (두 겹):**
  1. **규칙 (제안):** `CLAUDE.md`의 "비밀값 처리 규칙". 값은 `.env`나 `wrangler secret`에 두고 코드는 환경변수로 읽는다. `.env.example`을 둔다. 대화에 붙여 넣은 키는 다시 출력하지 않는다. 훅을 `--no-verify`로 우회하지 않는다. 이미 push된 키는 히스토리 정리보다 재발급을 먼저 한다.
  2. **보장 (훅):** `hooks/pre-commit`을 전역 `core.hooksPath`로 연결한다. 비밀값 파일 이름(`.env*`, `.dev.vars`, `.pem`, 키 파일 등)과, 추가된 줄의 키·토큰 패턴(Anthropic, OpenAI, AWS, GitHub, Slack, HF, Notion, 하드코딩 대입 등)을 막는다. **출력할 때 값은 가린다.** 레포에 자체 pre-commit 훅이 있으면 이어서 실행한다.
  3. **사전 차단:** `hooks/gitignore_global`로 비밀값 파일이 처음부터 스테이징되지 않게 한다.
- **검증:** `tests/test-pre-commit.sh`. gitignore를 우회한 강제 스테이징(`git add -f`)까지 포함한 11개 케이스로, 차단해야 할 것은 막고 통과해야 할 것은 통과시키는지 확인한다.
- **트레이드오프:** 패턴 기반이라 오탐과 미탐이 있다. 오탐은 `SKIP_SECRET_CHECK=1`로 그 커밋만 넘긴다. 형식이 정해지지 않은 비밀값은 못 잡으므로 1번 규칙이 계속 필요하다.
